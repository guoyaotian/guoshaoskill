# 导出器使用说明

## 环境与范围

Python 3.10+，依赖 `python-docx>=1.1.2,<2`。在 Codex 桌面环境优先使用 `load_workspace_dependencies` 返回的 Python；其他环境使用已有 Python。首次运行先执行 `python -c "import docx; print(docx.__version__)"`。缺少依赖时，用同一个 Python 执行 `python -m pip install -r scripts/requirements.txt`；安装失败应报告环境问题，不伪称已生成成品。

以下命令从技能根目录执行；其他工作目录请把脚本和资源路径改为绝对路径。脚本只把草稿转成 Word，不自行读取 PDF/PPT、不做 OCR、不证明教学事实正确，也不自动完成视觉验收。所有文件操作在本地完成。

## 最小可运行示例

`assets/examples/script.md` 和 `assets/examples/lesson.md` 使用一个虚构的三页合作主题课件，供导出回归验证，不应当作真实源课件依据。先把输出目录改成自己的临时目录。

```powershell
python scripts/generate_word_docs.py --script-md assets/examples/script.md --lesson-md assets/examples/lesson.md --script-docx "D:\工作临时目录\合作班会逐字稿.docx" --lesson-docx "D:\工作临时目录\合作班会教案设计.docx" --source-pages 3
```

只检查草稿，不保存 Word：

```powershell
python scripts/generate_word_docs.py --script-md assets/examples/script.md --lesson-md assets/examples/lesson.md --source-pages 3 --check-only
```

用户只要逐字稿时，只传 `--script-md` 和 `--script-docx`；只要教案时，只传对应的 `--lesson-*`。批量处理时逐个课件建立独立草稿和页码映射，每个课件调用一次，使用包含课题的文件名；记录每次返回的实际路径和错误，不让一个课件失败导致其他草稿被清理。

## 参数与用户要求

| 参数 | 默认 | 用途 |
| --- | --- | --- |
| `--max-script-chars` | `3500` | 口播正文字数上限，按默认规范的明确口径计数；超出时报错，不自动删文 |
| `--source-pages` | 未设置 | 源文件真实物理页数，实际生产应提供；缺少时输出无法检查上界的警告 |
| `--page-labels` | `required` | `required` 要求环节页码；`optional` 可缺省但已有页码仍校验；`omit` 要求草稿移除页码标签 |
| `--lesson-structure` | `standard` | `custom` 用于用户指定的不同结构，关闭固定十章和基本信息字段检查，不关闭文本完整性检查 |
| `--board-policy` | `required` | `optional` 用于用户明确不需要板书的情况 |
| `--reference-docx` | 无 | 教案参考样式，自动采样范围见下文 |
| `--style-config` | 无 | 两份 Word 的显式样式 JSON，优先于参考样式 |
| `--on-exists` | `version` | 任一成品存在时整组另存同一个版本号；`error` 则停止。始终不覆盖已有文件 |
| `--check-only` | 关闭 | 解析和校验草稿/样式，不创建输出文件，不要求输出路径 |

用户要求自定义章节、无板书、无页码时，根据其实际要求组合 `--lesson-structure custom --board-policy optional --page-labels omit`，不要为省事在普通任务中关闭校验。自定义教案可在任意章节标题中标页码；若同时输出两份，页码覆盖仍需一致。

## Markdown 输入合同

- UTF-8 或 UTF-8 BOM。第一项必须是唯一的 `# 文档标题`；标题不加章节序号。只有标题、没有正文时拒绝导出。
- `## 章节` 映射 Word `Heading 1`，`### 环节` 映射 `Heading 2`；不支持更多层级。正文每个非空物理行对应一个 Word 段落，不把换行自动合并。
- 默认逐字稿二级标题及标准教案“教学过程”下三级标题须带页码。推荐 `（对应课件第1-3页）`，兼容 `（P1-P3）`、`（对应课件第1页）`，编号从 1 开始。
- 支持非嵌套 `**加粗**`、`*斜体*`、单反引号行内代码。复杂嵌套强调、下划线强调不支持，请改写为该子集或普通文字。
- 支持 `-`、`+`、`*` 无序列表和 `1.`/`1)` 有序列表，缩进为 0、2、4 个空格。有序标号保留原稿数值，不自动纠正或重排。
- 支持每行以 `|` 开头、单元格同在一行的 Markdown 表格，第二行必须是 `| --- | --- |`。每行列数相同，单元格字面竖线写 `\|`；不支持合并单元格、跨行单元格或嵌套结构。默认等宽列，复杂表格需人工调整后渲染。
- 围栏可用三个或更多反引号/波浪线，结束围栏必须为同种字符且长度不小于开始围栏。所有围栏必须闭合且非空。
- `board` 块转换为整块板书；旧稿在“板书设计”二级章节下使用 `text` 或无语言代码块也可。板书按章节含义定位，不依赖 `## 7.` 字样。块内文字原样保留，不解释 Markdown。
- `center` 块明确表示居中口号/儿歌，计入口播字数；不再按句子长度或具体词句猜测居中。
- `note` 块表示不口播的教师提示，使用较小的灰色字，不计入口播字数。普通文字不应为了规避字数上限而放入此块。
- 其他代码块按普通预格式文字保留。图片、链接、HTML、引用、脚注、分隔线等不属于支持范围；应转换为纯文本或其他受支持结构，拒绝以丢内容的方式继续。

## 参考教案与样式

`--reference-docx` 仅影响教案：采样参考文件第一节的纸张宽高/边距，以及 `Normal`、`Title`、`Heading 1`、`Heading 2` 四个命名样式的段落与文字属性。不会复制参考正文、页眉页脚、图片、个人信息或无关主题内容。

自动采样不复制主题、复杂继承链、直接格式、表格样式、分节布局或自动编号。很多学校教案把标题直接加粗而仍使用 Normal 样式，不能靠此参数完整还原。遇到这类文件，先人工读取实际字体、字号、行距和结构，用下述 JSON 明确配置；复杂模板须使用当前可用 Word 编辑工具适配并逐页核对，不能承诺像素级一致。参考模板的章节顺序与命名由起草过程遵循，不由导出器自动提取。

示例：

```json
{
  "body_font": "宋体",
  "heading_font": "黑体",
  "body_size": 12,
  "title_size": 18,
  "heading1_size": 14,
  "heading2_size": 12,
  "line_spacing": 1.35,
  "top_cm": 2.5,
  "bottom_cm": 2.5,
  "left_cm": 2.8,
  "right_cm": 2.8,
  "board_fill": "F7F7F7",
  "board_border": "808080"
}
```

以上为全部支持的键，允许仅填写要覆盖的项目。字号单位为 pt，页边距单位为 cm，行距是倍数，颜色为不带 `#` 的六位十六进制。未知键或导致正文区域不足的边距会报错。默认纸张为 A4；参考 DOCX 明确使用其他纸张时遵循参考。

## 检查结果与失败处理

成功返回 JSON：实际输出路径、口播字数、来源覆盖页、警告，以及导出文本回读状态。`semantic_review` 与 `visual_review` 始终注明仍待人工/渲染验收；不能把文件保存成功当作教学和版面均合格。

导出前先校验所有草稿，保存到同目录临时文件并回读比对全部段落和表格文字，之后再通过独占创建保留一组输出文件名。普通运行异常会回滚本次新建成品、清理脚本自己的暂存文件，保留草稿和既有文件。进程强杀或断电时不能保证两个文件作为整体原子提交；若发现残留，先识别归属和完整性再恢复，不批量删除目录。

输入校验失败返回退出码 2，说明问题和可用时的行号；修正草稿或配置后重跑。输出目录不可写、参考文件损坏或成品被外部程序占用时，保留输入并处理具体错误，不连续无限重试。

最终仍需按默认内容规范做教学验收，并用当前环境的 Word 渲染器逐页查看实际文件。脚本没有绑定特定渲染器；缺少渲染能力时明确告知视觉检查未完成。
